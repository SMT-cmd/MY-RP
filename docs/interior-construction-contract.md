# Interior construction and room contract

The main home supports interior wall lines and a doorway offset, rather than a single mandatory open room. Partitions live on tile edges; they do not silently consume a whole floor tile. Horizontal edges run along X and vertical edges along Y. Exterior bounds remain fixed at the current home dimensions. Doorways stay passable and both adjacent tiles must remain clear. The command engine checks the current home/location, ownership and layout version before editing.

A personal starter shelter permits interior editing. Titled structural alterations belong to the current owner; tenants retain furniture, room-name and floor-finish controls without receiving structural powers. Leaving/selling a home preserves spent construction in the property, returns personal furniture to storage and revokes former interior access. Starter fixture reprovisioning searches for a valid position around existing walls without duplicating grants; optional fixtures remain stored if they cannot fit. The protected bed and pantry must remain usable.

The authored development rules charge 2,500 minor units per wall segment plus 1,000 for one doorway, and consume one local building-material unit per three segments, rounded up. These are fictional game prices awaiting overall balance acceptance. A line is at most twenty segments and a home holds at most one hundred. The review shows labour, owned-material quantity and removal terms. Materials can be acquired through the existing finite NPC/personal inventory contract. Building consumes real unexpired local inventory and posts balanced labour payment in the same transaction. Repeating a construction identifier returns its original receipt without consuming or building again.

Reject duplicate/out-of-bounds edges, lines through furniture, blocked doorways and any arrangement leaving a free floor tile, exit or fixture unreachable. Fixture interaction checks the intervening wall edge; being next to a bed through a wall does not grant rest. Placement uses the same checks. Movement and client approach paths cross only clear edges/doorways. Removing selected segments requires explicit no-refund consent and preserves the construction journals. Removing a doorway segment leaves an opening and can merge the geometric room areas.

Room areas are derived from partition boundaries, treating doorways as room boundaries for labels and as passages for navigation. Residents can name each area and select its floor finish. Names use text rendering and bounded lengths. Finishes and labels grant no currency, credentials, clinical effect or extra storage. Walls/floors and individual furniture finishes remain separate controls.

The 3D scene draws canonical edges, doorway frames and per-room floor colours. A wall-height control switches between full height and cutaway viewing. Canvas renders the same edge layout; labelled DOM forms permit all construction and room changes. Floor-placement advice detects wall crossings/door occupancy; the server remains responsible for final reachability. Changing a layout version cancels an older client route.

Home JSON mirrors carry the saved layout. The additive private PostgreSQL constraint verifies bounds/uniqueness, construction receipts, exact consumed stock/labour journals, furniture/wall conflicts, clear door tiles and recursive floor/fixture reachability. It adds no browser Data API surface or new service credential. Existing homes without partitions remain compatible.

Evidence covers exact/idempotent construction, invalid/no-material/stale edits, through-wall interaction rejection, door traversal, room finishes, tenant permissions, protected reprovisioning, backup integrity, real HTTP/DOM material purchase/construction, 3D edge geometry, SQL rollback/reopening/replay and SQL conflict/evidence rejection. Unique property door addresses, guest permission/visiting, multiple floors, extensions, structural contracting/manufacturing, GPU/device performance and final production art still require implementation or acceptance.
