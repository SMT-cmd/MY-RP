# Public PWA and low-data component

Components of R052, R053 and R065–R067; full A20/A21 device/network acceptance remains open.

The public manifest defines root scope, standalone launch, theme and original 192/512 PNG icons. Installation uses the browser's available install prompt only after the user selects Install game. Unsupported installation APIs leave the normal web client usable. This does not claim app-store distribution or installation on every browser/device.

The root worker has an exact public-asset allowlist injected from the HTTP static routes. Its version is SHA-256 over the worker template and every public source asset, including engine dependencies and root HTML. A source/dependency change therefore changes worker bytes on the next server start. The worker response uses no-cache, a stable URL and root scope. New workers wait for old clients to close; there is no skipWaiting, forced reload or clearing of uncertain game intents. Activation deletes only obsolete myrp-public caches.

Installation precaches only five small public offline-help/style/icon assets. It does not eagerly download the 3D engine, game media or authenticated tutorial state. Partial installation failure removes its own incomplete cache. Other allowed public assets use network-first fetches with credentials omitted, then cached fallback. HTTP failure, redirects, opaque responses and private Cache-Control responses are not stored. Storage quota failure does not prevent returning a live public asset.

API routes, non-GET requests, authentication/development-key headers, query strings, cross-origin requests and unknown/private resources bypass the worker. Navigations are never cached: a failed network navigation can show only the public offline-help screen. No cache contains balances, profiles, inventories, receipts, access/refresh tokens or economic command queues. The existing pending intent remains account-bound in tab session storage, and only the authenticated server resolves its original identifier.

Data saver uses the device saveData preference unless the player explicitly overrides it. It selects Low/text controls before world rendering and avoids loading the optional 3D engine. Only nonsecret data-saver/graphics preferences are saved locally. Disabling data saver restores the selected graphics mode. Existing accessible work, lessons, purchases and recovery remain server-authoritative. No audio/media feature is claimed by this component; later media must respect data saver before downloading.

Evidence: 140 automated checks pass, with focused HTTP/WebSocket regression after adding the explicit same-origin socket CSP source. A VM executes the actual worker returned by a real HTTP server against isolated CacheStorage, checking API/header/query/unknown-resource exclusion, public offline fallback, private-response rejection, partial-install/quota behavior and prefix-scoped cache deletion. HTTP checks verify worker headers and deterministic version, manifest and PNG dimensions. DOM checks verify explicit install consent, no automatic reload/storage deletion during update and usable low-data purchase/reconnect flow. TypeScript, browser-script syntax and whitespace checks pass.

This is controlled runtime/DOM evidence, not native browser installation, actual worker activation, Safari/Android testing, weak-network benchmarks, art compression/streaming or accessibility/performance certification. Those remain prelaunch gates. No push, main deployment, preview update or extra hosted resource was created.

Implementation references consulted: [Chrome service-worker lifecycle](https://developer.chrome.com/docs/workbox/service-worker-lifecycle) and [Mozilla CacheStorage documentation](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage). Exact WebSocket origins are included in CSP alongside self; see [Mozilla connect-src documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src).
