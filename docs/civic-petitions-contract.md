# Civic petition component

Implemented on 12 October 2026. This advances R043/A26; it does not complete lobbying, unions, associations, protests, elections or the whole game. Deployment remains held.

An adult registered citizen can propose one of five authored service-review subjects in their registered state, or privately support an existing request. Travel does not change civic registration. The proposer explicitly consents to publish their citizen name and to add their own support. Other signer identities and receipt keys never appear in the state petition panel or live frames. The panel exposes aggregate support, the viewer's own controls, the published proposer name and the subject. This is in-game sharing among same-state authenticated citizens, not a public web feed.

Proposed D33 development terms: seven-day signing window, ten supporters, one proposal per rolling day, four alternating support changes per citizen including initial support, and consideration available one day after the first threshold notice. Versioned terms and current petition version are checked on every action. Subjects have preliminary integer-minor-unit estimates: roads/housing 100000, water 150000, school 75000, clinic 125000. These parameters need gameplay/budget review before release.

Duplicate open state/subject proposals fail. The initial support and subsequent consent/withdrawal records alternate and retain immutable evidence. Withdrawals remain available after deadline, author withdrawal or consideration; four changes always end with withdrawn support. The author can close a petition before consideration. A threshold crossing produces one durable formal notice. Falling below the threshold or later withdrawal does not erase it. The signing deadline derives from the server clock without a business write; connected panels refresh at an unchanged cursor and preserve control focus.

After the delay, a same-state citizen can request the deterministic NPC civic desk's one consideration record. It snapshots current support, the journal-backed state treasury and the preliminary estimate. Outcomes are withdrawn, insufficient support, funding proposal required or formal budget review required. Neither the threshold nor consideration spends money, passes a law, changes a service, issues a qualification or grants government office. Actual budgets, appropriation, procurement, office eligibility, human official routing and scheduled unattended consideration remain separate prelaunch work. The initial panel offers a request rather than pretending that a human official has acted.

All commands use the authenticated actor, atomic state change, immutable receipt/outbox evidence and existing request-ID replay. Lost responses recover the original receipt. Stale versions, forged jurisdiction/actor payloads, missing consent, duplicate support and unsupported review fail. File and backup restoration reconstruct exact civic state in durable event order, including same-clock support/withdrawal and historical treasury snapshots. Money-moving civic receipts are rejected. The SQL adapter mirrors each petition under private `civic.petition`; invoker functions reconstruct it from immutable database receipts in revision order, validate jurisdiction/consent/limits/threshold/treasury, reject orphan or changed terms/evidence and reconcile the world and mirror at transaction commit. Existing world RLS and server scope apply; browser roles receive no new access.

The panel shows the newest fifty same-state records plus open petitions, pending notices and the viewer's older active support so withdrawal stays accessible. Archive search/pagination, operational retention/appeal/moderation and nationwide district/LGA petitions remain open. Free-form political text is not accepted by this authored-subject component.

Validation: domain permission/consent/clock/version/replay/threshold/expiry/withdrawal/no-money tests; actual company-tax treasury snapshots and later revenue; file restart/concurrent duplicate settlement; backup history tampering; two actual HTTP/WebSocket-to-DOM clients with lost proposal retry, support/withdrawal, NPC consideration, idle expiry without business writes, stable focus and revoked-session clearing; embedded SQL rollback/reopening, forged mirror/signature/notice/treasury rejection, terminal immutability, cross-world isolation and browser-role denial. Full-suite counts and hosted application evidence are recorded in project status.
